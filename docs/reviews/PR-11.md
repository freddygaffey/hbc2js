## Findings

**F2 — the disassembler bug reproduces exactly as claimed, and the fix is
verified red→green.** In a scratch worktree merged onto current `origin/main`,
reverting `src/disasm/print.ts` to `origin/main`'s pre-PR version and running
`node --test tests/gate/oracle/disasm/hermesc.test.ts` fails exactly
`56-switch-string-jumptable v98` and `v99` (265 pass / 3 fail — the third
failure is a knock-on `tests` counter artefact of the same two subtests),
with the diff starting at the claimed line: `ours="JTHDR" theirs="JT 146"`
then a run of `JTE n m` off-by-one lines — a one-line shift matching the PR's
description precisely. Restoring the committed fix makes the same run
268/268 pass. The fixture + the 7.A oracle *is* the regression test (CLAUDE.md's
bug-fix rule is satisfied): the test was red before the fix and green after,
using the new fixture as the only reproducer — no fixture in the corpus
exercised `StringSwitchImm` before this PR.

**F3 — catalogue rows 8/26 are honestly justified by the actual dump.**
Independently ran `node src/cli.ts disasm --mode raw` on
`56-switch-string-jumptable/v{84,94,96,98,99}.hbc` and counted opcodes:
`StringSwitchImm`/`JStrictEqual` = 0/28, 0/28, 0/28, 1/4, 1/4 — matches
`docs/LOWERING-CATALOGUE.md` row 8 and `docs/lowering/switch.md` §2d's table
exactly, confirming the v96→v98 boundary and that the small `bucket` switch in
the same module stays a compare chain at every version. For
`57-logical-assignment/v99.hbc`, `grep -n "JNotEqual\|LoadConstNull"` shows
`LoadConstNull r8` feeding three `JNotEqual …, r8` sites (the `??=` cases at
lines 58/63/95 of the raw dump) — matches `docs/lowering/logical-assignment.md`
§2c's claimed idiom. Both rows' flip to ✅ in the catalogue is measured, not
overclaimed.

**F4 — both fixtures are deterministic, print()-only, and `expected.txt` is
exactly right.** Read both `source.js` files: `56-switch-string-jumptable`
just iterates a fixed array through two pure switch functions;
`57-logical-assignment` has no randomness, dates, or ordering-sensitive object
iteration (getter/setter call order is observable and intentional, not
incidental). Ran both under plain Node (`global.print = console.log`) and
diffed against the committed `expected.txt` byte-for-byte — identical,
including the double-space in `57`'s first output line (`d = ''` printed
between two other fields). No `versions.txt` (compiles at all five versions,
as claimed); no `.obf`/`.min` variants, which the task brief says are not
required. `licence.txt` for both matches the standard Tier-1
original-work/MIT boilerplate used by every other construct fixture
byte-for-byte.

**F5 — `docs/lowering/switch.md` and `docs/lowering/logical-assignment.md`
are left self-contradictory (needs fix before merge).**
- `docs/lowering/switch.md:5-7`: the confidence line now reads *"✅ verified
  (compare chain, `SwitchImm`/`UIntSwitchImm` and — since T9 — `StringSwitchImm`,
  all four versions); ⛔ inferred (`StringSwitchImm` — ad hoc probe file, not a
  fixture; see catalogue O-3)"* — the first clause says `StringSwitchImm` is
  now verified, the second clause (left over from the pre-PR text, not
  deleted) says the opposite in the same sentence. The `**Fixtures:**` list on
  line 3 also wasn't updated to include `56-switch-string-jumptable`, even
  though §2d now cites it as the source of the table. Fix: delete the stale
  `⛔ inferred …` clause and add `56-switch-string-jumptable` to the fixtures
  line.
- `docs/lowering/logical-assignment.md:3-9`: opens with **"Fixture: none — no
  construct fixture … exercises these operators"**, then four lines later

  bolded headline fact is stale and contradicts the very next sentence. Fix:
  change the opening to `**Fixture:** `57-logical-assignment`` (or similar)
  and keep the historical note as context, not as the current fact.

Neither issue is a code or measurement defect — the underlying catalogue
