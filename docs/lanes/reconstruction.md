## Gotchas
- Whole-bundle pass ladder + emit on NSW: ~5 minutes and multi-GB; that is why the NSW artifact was produced flat. Anything per module must go through `decompileFunction` (one analysis, then per-subtree work) and must never re-parse the bundle per module (readability lane queue item 4 is the same fix; coordinate via the pack, do not duplicate).
- The naming overlay and the readability layer's `suggested` names apply at render time; a readable render that ignores the overlay throws away every name the LLM layer produced.
- `--jsx` output is JSX, not JS: the byte-identity/equiv guards are off for it by design (D20). A readable per-module render must say which tier it is (flat / passes / passes+jsx / +names) in its header comment and in the artifact manifest.
- `modules.json.deps` is a flat id list: it cannot tell eager `require()` (factory init) from lazy (inside a render function). The IR shows it; the index does not.
- String-grep for `"...Screen"` finds enums and content tables as often as components; only a body that calls `jsx`/`jsxs`/`createElement` is a component.
- `lottie-react-native` is a real native module in the NSW APK but absent from `deps.json` and `native.jsonl`: the native hint registry has gaps. `react-native-biometrics` was asserted by an earlier brief but no smali matches: unresolved, do not assume either way.
- `deps.json.reactNativeVersionConsistentWithHbc` is false for RN 0.72.17 + HBC v96, which is a normal pairing: the expected-range table is probably too strict.
